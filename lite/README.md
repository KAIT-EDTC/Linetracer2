## 2. 変更点と理由

### 2.1 rev.L1 → rev.L2 の変更

| # | 変更 | 理由・気をつけたこと |
|---|------|-------------------|
| 1 | **マイコン Pico → XIAO ESP32C6**（秋月 129481） | 依頼。21 × 17.8 mm と小さく、端がキャスタレーション（半分に切ったスルーホール）なので Pico と同じく**基板にじかにはんだ付け**できる。専用フットプリント `XIAO_ESP32C6_DirectSolder` を作った（§4.2） |
| 2 | XIAO を**右の端**に置き、**USB-C を右に向けた**（口が基板の端から 0.6 mm 出る） | XIAO の ADC ピン D0〜D2 が前の列（センサー側）に来て、センサーの線が短い。後ろの列はモータードライバーへの線だけ（§3.1） |
| 3 | **センサー LBR-123F → LBR-127HLD**（秋月 104500） | 依頼。本体が 8.7 × 4.5 × **高さ 5.6 mm**（LBR-123F は 1.5 mm）。長い辺を左右に向けて、間隔 12 mm（x = 38 / 50 / 62）は同じ |
| 4 | **スキッドを 4.0 → 7.5 mm**（`skid_clip_h75.stl`、新しく印刷） | センサーが背高なので、基板の前を床から 7.6 mm 以上にしないとセンサーが床に当たる。後ろは車輪で高さが決まるので、**ロボットが後ろに 2.9° 傾く**。センサーと床は約 2.25 mm（§4.4） |
| 5 | ピンの割り当てを全部やり直し（§3.1） | ESP32-C6 の起動のときのピンの状態に合わせた: **IN1〜IN4 は GPIO18〜23**（リセット中だけプルアップ）、**STBY は RX、赤 LED は TX**（起動ログや REPL の信号が出ても困らない出力）。どの瞬間もモーターは回らない（§3.1）。ボタンを RX につなぐとチャタリングで Ctrl-C が入りうるので避けた |
| 6 | **電池電圧の測定をやめた** | XIAO の ADC は 3 本だけ（§3.3）。ソフトは電池の電圧を決め打ち（`BATTERY_VOLT = 4.2`）にした |
| 7 | **J2（I2C の穴）を削除** | 信号ピンが 11 本しかなく、全部使っている |
| 8 | Q1・R7 は前の左の角のまま、START ボタンは**左**、赤 LED は **XIAO のとなり** | LED の線（D6）が数 mm で済む。XIAO の後ろの列からの線をドライバー以外へ出すと、自動配線が毎回 1 本失敗した（§2.3） |
| 9 | XIAO のアンテナの下とその先 4 mm を**両面とも銅なし**に | Wi-Fi / Bluetooth を使うとき電波が弱くならないように（走らせるだけなら関係ない） |
| 10 | モーターの 0.1 µF（C3/C4）は枠の切り欠きの中（y 57.5） | rev.L1 で 1 mm 後ろにずらした理由（Pico のパッド）がなくなった。ドライバーとの間を 1 mm 以上空けた |

**変えていないもの**: 枠のねじ穴 4 つ、スキッドの穴 (50, 11)、モーターのパッド（M1・M2）、回路の定数（100 Ω・10 kΩ・1 kΩ・470 µF・1N5819）、枠・デッキ・平歯車・車輪・TPU タイヤの STL、ねじ。

### 2.2 「いらない部品」の見直し

| 部品 | 結論 | 理由 |
|------|------|------|
| J2（I2C の穴、0 円） | **削除** | つなぐピンが残らない |
| D1 1N5819 | 必要 | XIAO の 5V ピンは **USB の VBUS そのもの**。ダイオードが無いと、USB をつないだとき USB の 5 V が単3電池に流れ込む（Seeed の資料も「5V ピンに外部電源を入れるならダイオードを入れる」） |
| C2 470 µF（VSYS） | 必要（むしろ大事になった） | XIAO の電源は降圧（SGM6029）だけで、Pico のように昇圧できない。モーターが動き出す瞬間に電池の電圧が下がると XIAO がリセットしやすいので、D1 の後ろで支える |
| Q1・R7（赤外 LED の ON/OFF） | 必要 | 外乱光キャンセル（LED を消したときの値を引く）に使う。LED 3 個 60 mA は GPIO 1 本では流せない |
| R4〜R6 10 kΩ（センサーのプルアップ） | 必要 | ESP32 は ADC に使うピンの内部プルアップが切れる（値もばらつく約 45 kΩ） |
| D2・R8（赤 LED） | 残した | XIAO にも黄色の LED（GPIO15）があるが小さく、同じ USB 側の端に充電ランプ（赤）もあって子どもが見分けにくい。依頼の「LED 1 個」もこの赤 LED。XIAO の黄 LED は 2 個目として使う |
| C1・C3・C4 | 必要 | モーターの電源とノイズ対策（標準版と同じ） |

### 2.3 子ども向けの見直し（2026-10-05 3 回目の依頼）

依頼: 「子どもたちが判断しやすいように、部品どうしの余白をもう少し取る。基板もできれば小さく。シルクは小学校低学年でも分かるように」

| # | 変更 | 理由・気をつけたこと |
|---|------|-------------------|
| 1 | **基板を 65 × 100 mm の長方形に**（rev.L2 前半は 100 × 100 mm、後ろの両角を切り欠き） | 枠が乗る後ろの部分は前から幅 65 mm（x 17.5〜82.5）。前の部分を同じ幅にそろえた。車輪・平歯車・枠の外側の軸受けは、前の切り欠きと同じく基板の外に出る（OpenSCAD で干渉なしを確認、§4.4）。面積 −27% |
| 2 | **抵抗 8 本を 6 mm おきに**（本体どうしのすき間 3.5 mm）。センサーの抵抗は 1 列にそろえた | 前は 5.08 mm と 3.46 mm（すき間 1 mm）が混ざっていた。スキッドは真ん中の 2 本の間（12 mm） |
| 3 | 部品どうしの間（コートヤード）を 1 mm 以上、大きい部品（コンデンサ・コネクタ）は 1.5 mm 以上 | 電池コネクタ J1 の自作フットプリントのコートヤードが「+ −」の文字まで含んで大きすぎたので、本体 ＋ 0.5 mm に直した |
| 4 | モータードライバーを**横向き**にして、モーターのパッドの前に | 出力（OUT1〜4）がまっすぐ後ろのモーターのパッドへ。入力は前（XIAO 側）。右モーター M2 の＋は OUT4 にした（線が交差しないように。ソフトは `RIGHT_INVERT = False`） |
| 5 | **XIAO の後ろの列はモータードライバーへの線だけ**、ほかは前の列から | 後ろの列から LED やボタンへ線を出すと、ドライバーへの線と交差して自動配線が失敗した。並べ替えで 6 回中 2〜5 回は未配線 0 になる（いちばん短いものを採用。最終版は 6 回中 5 回） |
| 6 | **シルクは記号だけ、説明は手順書に**（§4.5、`docs/assembly.md`） | 依頼者の指示（2026-10-05）: 「全部の手順を書く必要はない。記号を付けて、手順書に書く」。基板には丸い数字（つくる順番）、＋、LED の絵、抵抗の 3 本目の色の名前、短い部品名だけ |

## 3. 回路

回路図: `docs/Linetracer2-Lite_schematic.pdf`。モータードライバ・センサー 1 個分の回路は標準版と同じ考え方（`../docs/03_circuit.md` §4・§5.1）。

### 3.1 ピン割り当て（rev.L2）

XIAO を USB を上にして上から見たときのピン番号。基板の上では **USB が右**、ピン 1〜7（D0〜D6）が**前の列**（右から D0）、ピン 14〜8（5V〜D7）が**後ろの列**。

| XIAO ピン | GPIO | ネット名 | つながる先 | 起動のときの状態（ESP32-C6） |
|----------|------|----------|-----------|-----------------------------|
| 1 D0 | GPIO0 / ADC | SENS3 | **右**センサー PS3 | プルなし |
| 2 D1 | GPIO1 / ADC | SENS2 | **真ん中**センサー PS2 | プルなし |
| 3 D2 | GPIO2 / ADC | SENS1 | **左**センサー PS1 | プルなし |
| 4 D3 | GPIO21 | SW1 | START ボタン（内部プルアップ） | リセット中だけプルアップ |
| 5 D4 | GPIO22 | SENS_LED_EN | R7 1 kΩ → Q1（赤外 LED 3 個） | リセット中だけプルアップ（赤外 LED が一瞬つくが見えない） |
| 6 D5 | GPIO23 | MOT_IN2 | U2 IN2（左モーター） | リセット中だけプルアップ |
| 7 D6 | GPIO16（TX） | LED1 | 赤 LED D2（R8 1 kΩ） | 起動ログが出る（赤 LED がちらつく） |
| 8 D7 | GPIO17（RX） | MOT_STBY | U2 STBY | リセット中はプルなし、リセット後はプルアップ |
| 9 D8 | GPIO19 | MOT_IN4 | U2 IN4（右モーター） | リセット中だけプルアップ |
| 10 D9 | GPIO20 | MOT_IN3 | U2 IN3（右モーター） | 同上 |
| 11 D10 | GPIO18 | MOT_IN1 | U2 IN1（左モーター） | 同上 |
| 12 3V3 | — | +3V3 | センサーの抵抗（XIAO の中の降圧電源の出力） | |
| 13 GND | — | GND | | |
| 14 5V | — | VSYS | D1 の後ろ（電池 − 0.3 V）。USB をつなぐと USB の 5 V | |
| （XIAO の上） | GPIO15 | — | 黄色の LED（**0 で点灯**）。2 個目の表示に使える | |

- **モーターが勝手に回らない理由**: リセット中は IN1〜IN4 がプルアップで H、STBY（RX）はプルなしでドライバの中の 150 kΩ プルダウンにより L（＝待機）。リセットが終わると IN1〜IN4 はプルなしになりドライバのプルダウンで L、STBY は RX のプルアップで H になるが、IN が全部 L なので「止まっている（L/L）」。プログラムが動くまでモーターは回らない。
- **TX/RX（GPIO16/17）**: 起動ログが出て、MicroPython は UART にも REPL を開いている。ここには「信号が出ても困らない出力」（赤 LED、STBY）だけをつないだ。**ボタンを RX につないではいけない**（押したときのバタつきが文字として REPL に入り、運が悪いと Ctrl-C ＝プログラム停止になる）。STBY の 100 ms ごとの 5 µs の L パルスは Ctrl-C の形にならない。
- 前の列の線は前と左へ、後ろの列の線はモータードライバーへだけ出るように並べた（§2.3）。

### 3.2 電源

```
単3×3 ─ VBAT ─┬─ モータードライバ VM（C1 470µF）
              └─ D1 1N5819 ─ VSYS（C2 470µF）─ XIAO 5V ピン ─[XIAO の中]─ ショットキー ─ 降圧 SGM6029 ─ 3V3
                                     USB-C の 5 V もここにつながる（D1 があるので電池には流れない）
```

- XIAO の 5V ピンは USB の VBUS と直結。XIAO の中で **ショットキー → 降圧 DC-DC（入力 2.5〜5.5 V）→ 3.3 V** になる（Seeed の回路図 v1.0）。
- 降圧なので、3.3 V を保てるのは **電池が約 4.0 V 以上**のとき（D1 ＋ XIAO の中のダイオードで約 0.6 V 下がり、降圧で少し下がる）。それより下がると 3.3 V も下がり、計算では電池が約 3.4 V（1 本 1.13 V）あたりで XIAO がリセットする（実測はまだ）。**アルカリ電池推奨**。ニッケル水素（3.6 V）は下限に近いので、走り出しでリセットするようなら電池を充電する。
- **単3×4本は不可**（新品アルカリ 6.4 V。XIAO の 5V 入力には 5.6 V ツェナーを使った過電圧の保護回路があり、6 V あたりを超えると働く）。
- XIAO の裏の **BAT＋/BAT− パッドには何もつながない**（リチウムイオン電池用の充電回路につながっている。乾電池をつなぐと USB をつないだときに充電しようとして危ない）。基板側はこのパッドの下を銅なしにしてある。
- 電池だけで動かしているとき、XIAO の**充電ランプ（赤）が点滅することがある**（リチウム電池が無いため。故障ではない）。

### 3.3 電池電圧は測れない

- XIAO ESP32C6 で ADC が使えるピンは **D0〜D2（GPIO0〜2）の 3 本だけ**。ほかの ADC（GPIO4〜6）は裏の小さなテストパッドにしか出ておらず、子どもがはんだ付けできない。Pico のような「中で VSYS を分圧して測るピン」も無い。
- センサー 3 個で ADC を使い切るので、**電池電圧は測らないことにした**。ソフトは電池の電圧を **`BATTERY_VOLT = 4.2`（アルカリ 3 本で走っているときの目安）と決め打ち**してモーターの電圧を計算する。
  - 電池が減ると**だんだん遅くなる**（rev.L1 までは電圧に合わせてデューティを上げていた）。
  - 電池がほぼ空になると、**モーターが動き出した瞬間に XIAO がリセットする**（赤 LED が消えて最初からになる）→ 電池を替えるサイン。
  - ニッケル水素電池なら `linetracer.py` の `BATTERY_VOLT` を 3.7 にする。
- どうしても測りたいときの案（今回は採用しない）: センサーを 2 個にして D0 を空ける／アナログスイッチを足す（部品が増える）。

### 3.4 センサー（LBR-127HLD）

- 赤外 LED: (3.3 V − VF 1.2 V − Q1 0.1 V) ÷ 100 Ω ≒ **20 mA**（最大 60 mA）。3 個で約 60 mA を Q1 で ON/OFF（外乱光キャンセルは標準版と同じ）。
- フォトトランジスタ: 10 kΩ でプルアップ（白 → 電圧が下がる、黒 → 3.3 V 近く）。光電流は IF 20 mA で 0.2 mA 以上（データシート）→ 白で 2 V 以上下がる見込み。
- 1 回の読み取り: LED 点灯 0.3 ms → 3 個読む → 消灯 0.3 ms → 3 個読む ＝ 約 0.7 ms。
- **データシートに床との距離のグラフが無い**ので、ちょうどよい高さは試作で確かめる（§10）。スキッド 7.0 / 7.5 / 8.0 mm で約 1.7 / 2.25 / 2.8 mm に変えられる。

### 4.2 XIAO 直付けのフットプリント `Linetracer2:XIAO_ESP32C6_DirectSolder`

`../scripts/gen_lib.py`（共通）の `fp_xiao_direct()` で作る。寸法は Seeed の KiCad データ（XIAO ESP32C6 v1.0 の基板そのもの）から測った。

- **1 ピンに 1 つのスルーホールパッド**。穴（φ1.0）は XIAO のピンヘッダ用の穴の真下（中心から ±7.62 mm。ピンヘッダでも付けられる）、銅は外側へ伸ばして **XIAO の端から 1.9 mm はみ出す**（4.0 × 1.7 mm の長円）。こてを「基板のパッド」と「XIAO の半円の穴」に同時に当てられる。
- **XIAO の裏のむき出しのパッドの下は表の銅禁止**（配線・ビア・ベタなし）: 電池用 BAT＋/GND、3V3・BOOT・EN・JTAG のテストパッドが中央の幅 ±1.9 mm に並んでいる。
- **USB-C の殻の足 4 本**（XIAO を貫通して裏に出る）の下に逃げ穴 φ1.8（銅なし）。XIAO が浮かないように。
- **アンテナの下とその先 4 mm は両面とも銅なし**（配線・ビア・ベタ・パッド禁止）。
- 3D モデルは簡単な箱の組み合わせ（`../scripts/gen_3d.py`）。

### 4.3 配置

```
 前 ───────────────────────────────────────────────
  Q1 ④  ▲まえ   [S1]     [S2]      [S3]
  R7  R1 R4 R2  (スキッド)  R5 R3 R6        （抵抗は 6 mm おき）
                                ①
  SW1 スタート ④          LED④ R8  ┌── XIAO ESP32C6 ⑧──┐
                                  D2  │ マイコン      USB ─┼→ USB-C
  Linetracer2 Lite                     └────────────────────┘
  C2 ⑥  ┌ U2 ⑦ モーター ドライバー  1 ┐ C1 ⑥  J1 ⑤ でんち  D1 ②
         └──────────────────────────────┘
            C3 ③ [M1 −  +]  ⑩  [M2 −  +] C4
 ───────── 枠・モーター・電池ボックス（後ろ 40 mm）─────────
 後
```

- センサーは基板の**裏**（レンズが床を向く）。LED 側（面取りした角）が左、フォトトランジスタ側が右（上から見て）。左の抵抗が 100 Ω（LED）、右が 10 kΩ（プルアップ）。
- XIAO のアンテナの下とその先 4 mm（XIAO の左側）は両面とも銅なし。赤 LED はそのすぐ左。
- 基板の生成手順・自動配線は標準版と同じ（6 回試して最短を採用、§9）。6 回とも未配線が残ったら `build_pcb.py 10` などで回数を増やす。

### 4.4 センサーの高さとスキッド（機械）

- LBR-127HLD は高さ 5.6 mm。標準版の高さ（基板の下面が床から 4.0 mm）のままだと**床に 1.6 mm めり込む**。
- 枠・車輪は変えずに、**前のスキッドだけ高く（7.5 mm）**した。後ろの高さは車輪で決まるので、ロボットは**後ろに 2.9° 傾く**（前が上がる）。2.9° なら重心・ギヤ・電池ボックスには影響しない。
- `../hardware/mechanical/linetracer2_mech.scad` を `-D LITE=true` で開くと、傾きと床とのすき間を表示する（タイヤ φ31.2 の TPU で計算）:

| スキッド | 傾き | センサーと床 | 基板の前の端と床 | 後ろのねじ頭と床 |
|---|---|---|---|---|
| `skid_clip_h70.stl` | 2.5° | 1.7 mm | 7.5 mm | 1.2 mm |
| **`skid_clip_h75.stl`（標準）** | **2.9°** | **2.25 mm** | 8.0 mm | 1.1 mm |
| `skid_clip_h80.stl` | 3.3° | 2.8 mm | 8.6 mm | 1.1 mm |

- スキッドとセンサー・基板の干渉チェックは OpenSCAD で「空」を確認（わざと 2 mm 前に置くと重なりを検出することも確認）。基板を 65 × 100 mm にしたあとも、枠・モーター・デッキ・電池ボックスのチェックはすべて「空」。
- 車輪を大きく（φ40）すれば水平のまま上げられるが、枠・速さ（1.3 倍）・トルクが全部変わるのでやめた。

## 7. 性能への影響

3 センサーでの走り方（見つけられる線の幅 ±21.5 mm、5 段階の位置、Kp の初期値など）は rev.L1 と同じ（センサーの間隔が同じ 12 mm）。

| 項目 | rev.L1 | rev.L2 |
|------|--------|--------|
| 1 回の読み取り | 約 0.7 ms | 約 0.7 ms（ESP32 の ADC は 1 回数十 µs） |
| モーターの電圧 | 電池の電圧を測って補正 | **決め打ち**（電池が減ると遅くなる） |
| 電池の下限（計算） | 約 2.1 V（Pico は昇降圧） | **約 3.4 V**（XIAO は降圧のみ。アルカリなら 1 本 1.1 V 強まで） |
| ロボットの姿勢 | 水平 | **後ろに 2.9° 傾く** |

- 線を見失ったら最後に見えた側へ強く曲がる処理、D（微分）のフィルタ `d_f` は rev.L1 と同じ。**`main.py` の `LEVELS` は実機で調整が必要**。

## 8. ソフト（`firmware/micropython/`）

### 8.1 MicroPython を入れる

1. micropython.org の **ESP32_GENERIC_C6**（ESP32-C6 用の公式ファームウェア、2026-08 時点 v1.29.0）を使う。
2. **Thonny**: 「ツール → オプション → インタプリタ」で「MicroPython (ESP32)」を選び、「MicroPython をインストールまたは更新（esptool）」で family **ESP32-C6** を選んで書き込む。一覧に無いときは esptool で:

```bash
pip install esptool
```

```bash
esptool.py --chip esp32c6 erase_flash
```

```bash
esptool.py --chip esp32c6 --baud 460800 write_flash 0 ESP32_GENERIC_C6-20260824-v1.29.0.bin
```

3. 書き込めないときは、XIAO の **BOOT ボタンを押したまま USB を差す**（またはBOOT を押しながら RESET を押して離す）と書き込みモードになる。
4. `linetracer.py` と `main.py` を XIAO に保存（Thonny:「/ にアップロード」）。

### 8.2 ライブラリの使い方（rev.L1 との違い）

```python
from linetracer import Robot
robot = Robot()

v = robot.sensors.read()        # [S1, S2, S3] 0(白)〜1000(黒)
pos = robot.sensors.position()  # -1000(左)〜0(真ん中)〜+1000(右)、見失うと None
kind = robot.wait_press()       # ボタンを押して離すまで待つ → "short" か "long"（0.8 秒以上）
robot.blink(3)                  # 赤 LED を 3 回点滅（ブザーの代わり）
robot.led_xiao(True)            # XIAO の黄色い LED（2 個目の表示）
robot.motors.battery_volt = 3.7 # 電池の電圧（決め打ち）。ニッケル水素なら 3.7
```

- **`robot.battery` はなくなった**（電池電圧を測れないため）。
- ピン番号は ESP32-C6 の GPIO 番号（`Pin(16)` など）。表は §3.1。XIAO の「D0」などの名前は使わない。
- XIAO の黄 LED は **0 で点灯**（`Pin(15).value(0)` で光る）。

| 標準プログラム `main.py` | 操作 |
|------------------------|------|
| START を短く押す（1 回目） | 自動キャリブレーション（線の上で左右に回る） |
| START を短く押す（2 回目から） | 赤 LED が 3 回点滅して走り出す。もう一度押すと止まる |
| START を長押し（**赤 LED が消えたら離す**。XIAO の黄 LED も点く） | 速さのレベル 1→2→3→1。赤 LED がレベルの数だけ点滅 |
| 赤 LED が点きっぱなし | 準備 OK（電源ランプの代わり） |
| 走り出すと赤 LED が消えて止まる（XIAO がリセット） | 電池が少ない → 電池を替える |

授業のサンプル: `01_led_blink.py`（赤と黄の LED）、`02_button.py`（ボタン・押した回数）、`03_sensor_monitor.py`（3 個の値）、`04_motor_test.py`（標準版と同じ）、`05_simple_tracer.py`（S1 と S3 で ON/OFF 制御）。

> 標準版の `../firmware/micropython/` は Lite では動かない（ピンと ADC の使い方が違う）。rev.L1（Pico）のソフトも rev.L2 では動かない。

## 9. 作り直し方（スクリプト）

共通のスクリプト（リポジトリ直下の `scripts/`）に環境変数 `LT2_VARIANT=lite` を付けると、出力先が `lite/hardware/` になる。付けなければ標準版。Lite 専用のスクリプトは `lite/scripts/` にある。コマンドはリポジトリ直下の `scripts/` で実行する。

```bash
cd scripts
export LT2_VARIANT=lite
python3 gen_lib.py && python3 gen_3d.py && python3 gen_lib.py   # 2 回目で 3D モデルがフットプリントに入る
./kc fp upgrade ../lite/hardware/kicad/lib/Linetracer2.pretty && ./kc sym upgrade ../lite/hardware/kicad/lib/Linetracer2.kicad_sym
python3 gen_project.py
python3 ../lite/scripts/gen_schematic_lite.py && ./kc sch upgrade ../lite/hardware/kicad/Linetracer2-Lite.kicad_sch
./kc sch export netlist --format kicadsexpr -o ../lite/hardware/kicad/reports/Linetracer2-Lite.net ../lite/hardware/kicad/Linetracer2-Lite.kicad_sch
python3 build_pcb.py 6          # 配置（lite/scripts/gen_pcb_lite.py）→ 自動配線 → シルク（lite/scripts/post_pcb_lite.py）→ DRC、約 5 分
./kpy sync_pcb.py
./export_outputs.sh             # Gerber・BOM・PDF・STEP・3D 画像（lite/hardware/, lite/docs/）
```

スキッド（OpenSCAD、`hardware/mechanical/` で実行）:

```bash
~/.local/opt/openscad-2021/AppRun -D 'LITE=true' -D 'SKID_H=7.5' -D 'part="skid_clip"' -o skid_clip_h75.stl linetracer2_mech.scad
```

| ファイル | 役目 |
|---------|------|
| `scripts/kicad_env.py`（共通） | `LT2_VARIANT` で出力先（`hardware/kicad/` か `lite/hardware/kicad/`）とプロジェクト名を切り替え |
| `lite/scripts/gen_schematic_lite.py` | Lite の回路図 |
| `lite/scripts/gen_pcb_lite.py` | Lite の部品配置（`scripts/gen_pcb.py` の関数を使い、配置だけ差し替え）＋ねじ頭・スキッドのツメの下の配線禁止エリア |
| `lite/scripts/post_pcb_lite.py` | Lite のシルク |
| `scripts/gen_lib.py`（共通） | XIAO 直付けフットプリント（`fp_xiao_direct()`）、LBR-127HLD、XIAO のシンボル |
| `scripts/gen_3d.py`（共通） | 簡単な 3D モデル（XIAO、LBR-127HLD など） |
| `hardware/mechanical/linetracer2_mech.scad`（共通） | `-D LITE=true` でスキッド位置・センサー・TPU タイヤ・スキッド 7.5 mm を Lite にして干渉チェック、傾きを計算 |

## 10. まだ確かめていないこと（試作で見る）

- [ ] XIAO の直付けを子どもができるか（パッドのはみ出し 1.9 mm で足りるか、5V/GND/3V3 のブリッジ）
- [ ] USB-C のプラグが基板の端に当たらないか（口が 0.6 mm 出ている。当たるなら XIAO をもう 0.5 mm 前へ）
- [ ] **LBR-127HLD のちょうどよい高さ**（白と黒の差がいちばん大きいのはスキッド 7.0 / 7.5 / 8.0 mm のどれか。`03_sensor_monitor.py` で比べる）。差が小さければ R4〜R6 を 22 kΩ にする案も
- [ ] 2.9° 傾いた姿勢で、スキッドが段差やテープの継ぎ目に引っかからないか
- [ ] 電池の電圧が下がったとき、どこで XIAO がリセットするか（アルカリ・ニッケル水素）。`BATTERY_VOLT` の値
- [ ] 3 センサーでどのくらいの速さ・カーブまで走れるか（`LEVELS` の調整）
